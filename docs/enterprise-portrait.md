# AI 企业脸谱

入口：登录工作台 → 生态合作 → AI 企业脸谱，或 `/#ppt/portrait`。独立交互演示：`/enterprise-portrait/preview`，无需登录，所有演示企业、订单和案例均为虚构，演示记录不会写入业务数据库。

## 已实现的业务与交互

- 企业关系网络：Canvas 力导向布局、拖拽节点、滚轮缩放、画布平移、自适应、暂停动画、深浅色切换；企业列表为键盘操作提供替代入口。
- 企业画像：简介、行业、产品与能力标签、合作需求、案例、所在地及档案完整度。支持新建、编辑、提交审核及经理/管理员确认；已确认档案修改时先退回草稿，保存后重新审核。
- 网络/企业列表/合作机会三个视图；按企业、能力、需求、案例搜索，按行业和关联类型过滤；导出当前筛选网络及对应来源 JSON。
- 订单、合同、项目、交付版本、合作记录沿显式业务引用链建立关联；客户档案可连接企业档案。不会根据公司名称包含关系推定订单归属。
- 已确认需求和企业自行维护的合作需求与能力标签生成供需建议；共同能力单独标为能力关联。关键词分数只是可解释的规则匹配分，不是统计置信度或成交概率。
- AI 分析复用当前企业配置的 OpenAI/DeepSeek 模型。开始前展示范围与目的地；只将网络中的授权企业信息和来源摘要发送给已配置服务。
- AI 结果必须引用当前版本的来源及两个真实节点，且分别包含双方来源。无效结果被剔除，全部无效则报错且不保存；所有模型关系固定为待核对建议，不会覆盖事实关系。
- AI 结果按企业持久化，记录提供方与用量。资料版本或展示授权变化后，旧结果自动失效。45 秒刷新及手动刷新均不会自动调用模型。
- 「加入跟进」创建当前企业的真实 `followup` 记录，保留双方、关联依据与下一步动作。实际对外联系仍由业务人员办理。

## 数据范围

业务网络读取 `treasure_business_records`。当前企业仅使用本功能明确支持的业务类型；跨企业仅收录 `enterprise` / `demand` 且 `status=已确认`、`sharing=授权展示` 的记录，平台管理员也遵循此规则。外部字段再次按白名单筛选，不暴露联系人、电话、预算、内部知识或订单。查询和写入沿用现有登录态、企业成员权限、同源校验及版本校验。

`enterprise.profileType=本企业` 才明确映射到所属企业节点；其他档案为独立合作方节点，不因名字相似自动合并。`demand.enterpriseId` 可选，指定当前企业维护的需求所属档案；未指定时属于发布企业。

现有工作台 `PptState` 是示例资料空间，与真实业务台账保持分离。本功能的「业务数据」不把示例订单当成真实交易；「演示网络」为独立的虚构数据集。

没有新增数据库表或迁移。档案扩展字段沿用业务 JSON，分析结果为 `portraitAnalysis` 业务记录，用量写入现有集成用量表。

## 容量与当前边界

单次图谱读取最多 1,800 条业务资料、180 份企业档案及 180 个资料所属企业；超出会明确提示。模型单次分析最多 80 个节点、350 条来源，超出时规则网络仍可查看。该版本为按需分析，没有建立向量数据库、GraphRAG 索引或全量后台定时分析任务。

跨企业的订单和案例原文不自动公开；需要展示的案例请由企业录入授权档案。当前不推断股权、法律关系或真实成交概率。暂未做万级节点压测。

## 验证

```powershell
npm run typecheck
npm run build
npm run test:portrait
npm run test:portrait:api
```

逻辑测试覆盖隔离、字段脱敏、业务链、循环引用、草稿排除、供需归属和模型来源校验。接口测试创建独立的 `treasure_company_qa_*` MySQL 库，运行真实本地服务与模型 SDK，外部模型用模拟流替代，不消耗真实模型额度，完成后清理测试库。接口验收结果：`tmp/enterprise-portrait-api-verification.json`。

真实模型效果与真实业务人员验收需使用实际资料评估；模拟模型通过不等于真实模型完成验收。
