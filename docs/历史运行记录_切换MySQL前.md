## 当前边界

当前站点为所有者私有的演示工作空间。负责人字段用于分工，但尚未实现多用户账号与角色权限。公众号、小红书、视频号、现场 IoT、财务票务及租户小程序未连接。内部归档不代表已经向外部平台发布。房源、企业档案、水电、供需撮合与产业图谱提供明确标记的样例数据；图谱节点和匹配依据可交互查询，但尚未接入真实企业资料或语义模型。三维楼宇是生成的概念效果图，不是可旋转的 WebGL 模型。

没有模型凭据时，生成明确标为“模板演示生成”。提供服务端 `DEEPSEEK_API_KEY` 后，自动启用 DeepSeek `deepseek-v4-flash` 非思考模式。模型端点固定为官方 HTTPS 地址，凭据不发送到浏览器、不写入数据库。上下文检索是确定性的中文词组相关度排序，不是向量检索。政策知识缺少官方原文时只生成待核查提纲，不编造申报结论。

参考：[DeepSeek 官方 Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。真实模型调用需要接入方的有效账户和额度，当前未验证实际调用。

## 本地运行与部署

使用 Node.js 22.13+，执行 `npm ci`、`npm run dev`。D1 绑定名为 `DB`，开发数据库位于 `.wrangler/state`。首次本地使用需通过 Wrangler 对本地 `DB` 依次执行 `drizzle/0000_romantic_the_initiative.sql` 和 `drizzle/0001_tricky_gladiator.sql`；线上迁移由 Sites 部署自动应用。`db/schema.ts` 为结构定义，`npm run db:generate` 生成后续迁移。已部署迁移保持不变。

可选模型凭据在本地放入忽略的 `.env` / Cloudflare 本地环境文件，在线上通过 Sites 环境密钥配置。不要将任何密钥写入源码或客户端。

`npm run build` 生成 Cloudflare Workers ESM 与静态资源，`.openai/hosting.json` 保存既有站点 ID 与逻辑 D1 绑定。私有访问由 Sites 层控制，不应直接将此版本改为公开站点来承载团队私有资料。

## 财务管理

左侧“财务管理”提供企业账套、应收应付、费用报销、资金账户、收支账本与月度分析。数据保存到 D1；本地正式运行保存在 `data`。新增 `0003_finance_business.sql` 迁移，保留原有财税收支并归属运营账套，不生成虚构业务数据。

使用顺序：新建企业账套 → 新增资金账户并填写期初余额 → 创建应收、应付或报销单 → 审核 → 按实际收付登记。支持分次收付、逾期筛选、退回后修改重审、补充票据、原始凭证上传下载（PDF/PNG/JPG，800KB 内）、冲销、操作记录和 Excel 可打开的 UTF-8 CSV。每笔收付与冲销在同一数据库事务中同步单据、账户流水和账本；版本检查阻止重复或并发覆盖，金额按整数分保存。资金账户余额含期初余额，仅已确认收支影响余额。

流程参考 [ERPNext Accounts](https://github.com/frappe/erpnext/blob/develop/erpnext/accounts/README.md) 与 [Frappe Books](https://github.com/frappe/books)，按当前 React/D1 系统独立实现，未复制其代码或安装整套 ERP。当前提供本工作空间内部经营账本；多个账套是数据分类，尚无企业独立登录及员工/审批人权限隔离。收付款为人工登记，没有连接银行支付、电子发票或税务申报。未配置大模型时，月度分析由实际录入的账本数据和本地规则生成。

启动本地正式服务后运行 `node tests/finance-business.integration.mjs` 验证账套隔离、审核、部分收付、并发重放、冲销、凭证、手工账本和汇总。验收只创建带唯一标识的测试账套，结束后生成 `work/finance-test-cleanup.sql`；使用本地 Wrangler 清理该次测试记录，不作用于真实业务数据。

## 税务管理

左侧“税务管理”与财务管理共享企业账套，并保留当前浏览器会话的账套选择。提供发票台账、进项资料核对、财务待归集与申报日历。支持按实际票面金额和税额登记蓝字/红字票据、记录原票号码、人工核对人、进项资料处理状态、原票 PDF/图片、修改后重新核对和本地作废追溯。汇总按开票月份，仅包含已核对票据，红字冲减金额。财务来源按完整已审核业务单据或已确认手工收支归集，避免把分次付款重复作为发票；发票号码与关联来源均有重复登记拦截。

申报事项按企业实际核定期限设置所属期、截止日期、负责人和金额，按“待准备 → 资料齐备 → 已申报 → 已缴税”跟进。登记已申报须有回执号与实际日期，已缴税须有缴款参考号与实际日期。提供逾期提醒、发票/申报 CSV 和可导入日历的 ICS 文件。本地管理记录不代替税务系统的查验、抵扣认定、正式申报、发票作废或税款缴纳；系统未按外国 ERP 的税例套用中国税法，也不自动推断企业的适用税率、纳税身份和法定期限。

参考 [ERPNext Taxes](https://docs.frappe.io/erpnext/taxes)。新增 `0004_tax_management.sql` 迁移；`node tests/tax.integration.mjs` 验证票据核对、红字冲减、来源去重、凭证、申报流转、回执与账套隔离，生成只清理本次测试账套的 `work/tax-test-cleanup.sql`。
