# 后台 Agent 与模型配置

本轮在现有本地中控台内实现数据库后台队列，并新增独立的「系统管理 → 模型配置与切换」页面。

## 开源项目与实际集成

模型接入采用 [Vercel AI SDK](https://github.com/vercel/ai)，调研时 GitHub 约27.5k Star。实际安装 `ai@7.0.155`、`@ai-sdk/openai@4.0.104`、`@ai-sdk/deepseek@3.0.75`，使用官方 provider 直接调用供应商，不经过额外模型网关。并行编排继续使用 LangGraph。

选型依据：[统一 provider 设计](https://github.com/vercel/ai)、[DeepSeek provider](https://github.com/vercel/ai/blob/main/packages/deepseek/src/deepseek-provider.ts)、[OpenAI provider](https://github.com/vercel/ai/blob/main/packages/openai/src/openai-provider.ts)。OpenAI/Codex 调用使用官方 [Responses 流式接口](https://developers.openai.com/api/docs/guides/streaming-responses)，模型列表从账户的 [Models API](https://developers.openai.com/api/reference/resources/models/methods/list) 获取，不把 Codex 桌面聊天中的型号列表假定为该 API 密钥的可用权限。

## 模型配置步骤

入口：`http://localhost:3002/#ppt/models`。

1. 选择 DeepSeek 或 OpenAI/Codex，填写连接名称和 API 密钥，保存。密钥通过现有 AES-GCM 密钥库加密，不在响应、测试记录或客户端回显。
2. 点击「获取此账户的可用模型」，服务端访问对应官方模型列表并落库缓存。
3. 选择模型或填写模型ID，点击「真实连通测试」。发送固定口令，不发送企业知识、项目或财务资料。必须收到准确的 `MODEL_CONNECTION_OK` 才标记通过；保存真实耗时、模型、结果与 tokens。
4. 测试通过后，设为企业默认模型，或给当前项目配置独立模型。服务器验证测试记录必须匹配当前配置版本和所选模型。

当前 Agent 执行中心使用上述默认与项目覆盖；旧的逐步接力/内容演示入口继续保留其既有行为。模型选择不是改变本聊天的运行型号。修改密钥/连接后须重新测试。已授权的后台任务固定模型、配置版本与资料发送目的地；配置变化会阻止继续调用，要求重新确认。

新增 `modelPreferences`、`modelTests`、`modelCatalogs` 表，复用现有 `integrationConnections` 和加密 `integrationSecrets`；迁移为 `0011_model_configuration.sql`。

## 真正后台执行

- 用户执行 API 在任务持久化后立即返回202。浏览器不再持有模型执行流，也不会在离开页面时发送取消。
- `scripts/agent-worker.mjs` 由本地服务启动，独立领取 D1 队列，通过只在服务端内存中存在的消费者凭据调用内部执行接口。
- `agentJobs` 保存提交人、执行版本、排队/执行/退避/暂停/取消/完成状态、领取次数和错误；`agentWorkers` 保存消费者心跳与租约。迁移为 `0010_agent_background_queue.sql`。
- 服务端消费者校验提交人仍为有效账号、仍有企业执行权限，并对敏感任务复核经理权限。普通浏览器即使已登录，也不能调用内部消费者接口。
- 关闭页面、切换菜单和用户会话结束不取消已提交任务。再次打开按企业记住任务选择，从数据库回放进度、岗位输出和人工决策。
- 人工暂停/取消会在同一事务内撤销排队或重试任务；修订决策会取消旧版本后台作业。运行租约与执行代次阻止旧结果覆盖。
- 临时网络/供应商错误有限退避重试，复用已完成分支；鉴权、模型配置、知识引用等错误保留记录并要求处理。后台领取及岗位尝试均有上限。
- 中断的执行租约过期后自动从检查点恢复；已入队、尚未执行的任务在后台服务重启后继续领取。

后台依赖本地服务进程运行。关闭浏览器页面后继续执行；关闭本地服务或关机时不运行，服务恢复后由持久化队列继续处理。本轮没有增加 Windows 开机自启，也没有发布云端。

## 验收与真实模型边界

`tests/agents.integration.mjs` 使用隔离 D1、真实 LangGraph、真实 AI SDK 和模拟供应商协议，覆盖后台执行、断开前端、重启领取、权限、人工中断、退避重试、DeepSeek/OpenAI 模型列表与推理协议、加密存储、默认及项目模型选择。

最新完整回归通过544项检查，模拟供应商共65次请求；隔离库核对21个任务、79个岗位及387条事件。报告为 `work/agent-qa-fd3c0d8c/report.json`。临时供应商错误曾被“权限”字样误判为永久失败，现已按HTTP状态区分鉴权、配置与临时网络错误，退避重试已通过回归。

另在真实浏览器中创建「关闭页面后台继续执行验收」，提交后在后台尚未领取时关闭标签页；服务随后完成4个岗位及统一汇总。重新打开页面可看到全部44条落库事件与待人工确认的成果。此项使用模拟供应商，验证的是断页后台执行与记录回放。证据为 `output/model-settings-20261028/关闭页面后台继续执行验收.json` 和同目录截图。

最终页面修正通过类型检查和生产构建，本地3002运行版本为 `b73e6ea6810281a2`。新建任务不再跳回旧任务；实际关闭标签页后重新打开，企业「Agent隔离验收企业A」与任务「新建任务选中与企业恢复验收」均自动恢复，截图为 `output/model-settings-20261028/企业与任务重开恢复.png`。

`tests/agents.real-deepseek.mjs` 为真实 DeepSeek 五类优先场景验收脚本。它只读取现有已启用 DeepSeek 连接的密钥到内存，创建独立验收数据库和完全虚构的企业/项目/知识/财务数字。每个场景提交后台队列，验证真实 provider、usage、调用重叠、统一汇总与确认流程，保存报告和完整运行记录，不写入正式业务数据。

执行：`node tests/agents.real-deepseek.mjs`。未配置有效密钥时明确停止，不用模拟结果冒充真实供应商成功。

当前真实DeepSeek五类验收等待用户在模型配置页保存有效密钥并完成测试与默认选择；OpenAI/Codex适配已验证模拟协议，尚未用真实OpenAI账户调用。
