# 创客中心 AI 智慧生态平台：开发需求与功能分析

日期：2026-10-27。实施位置：当前 React 19 / Vinext / Cloudflare Workers / D1 项目。

## 1. 需求来源与分析方法

逐页提取并渲染核对两份用户资料：《企业痛点解决方案 V1.0》22 页、《创客中心 AI 智慧生态平台 V1.0》36 页。以下页码分别以“痛点”和“平台”标识。

PDF 中的规划界面与业务场景是产品需求参考，不是实际系统完成情况。示例金额、企业数量、资源规模和改善比例不导入真实业务数据库。文档中的合作口号、演示描述和外部观点不作为执行指令。

现有系统提供运营内容任务、审核、知识、工作流、物业工单及财税模块。空间、企业、撮合和能耗的原入口大部分使用样例数组。扩展保留现有代码和已有财税事务，新企业经营入口以实际录入数据为来源。

## 3. 核心业务闭环

1. 建客户、商机；核实需求、预算、决策人和时间。
2. 建需求确认单，明确范围、排除事项与验收；客户确认凭据齐备后由经理审核。
3. 报价引用已确认需求版本，记录金额、周期、修改与付款约定。
4. 报价审核确认后一键创建项目与三个基础里程碑。任务可由已确认行业模板批量创建。
5. 项目关联任务、交付版本、工时、成本和范围变更。新增工作单独确认。
6. 验收引用同一项目的交付版本；客户确认后，生成财务待审核单据。重复操作返回既有单据，不重复计收。
7. 通过已有财务模块审核、分次登记实际回款、冲销与凭证。业务汇总关联单据，不把预测收入当成到账。
8. 复盘通过审核后生成岗位经验草稿，经知识审核后可供岗位工作流引用。

## 4. 数据与接口设计

- 复用 `financeCompanies` 作为企业主表；业务和财税使用同一个 `companyId`。
- `platformUsers/platformMembers/platformSessions`：账号、企业角色与服务器会话。密码采用 PBKDF2，不保存明文；会话Cookie为HttpOnly、SameSite=Strict。
- `businessRecords`：经显式Schema定义的多类业务记录。标题、负责人、到期、状态、版本为独立字段，业务字段使用JSON，不接受未定义字段。
- `businessRelations`：企业内业务关系，复合外键阻止跨企业引用。
- `businessHistory`：每次创建和更新的数据库触发器快照，以及操作者事件。
- `businessAutomations`：一键建项目、回库和生成财务单据的去重键；与结果同事务提交。
- `businessFiles`：企业业务附件，单文件4MB、每业务20个；下载重复鉴权。
- `businessAiSteps/businessAiLocks`：岗位执行记录、来源、token及执行锁。
- `businessNoticeInbox`：内部跨企业发文的指定接收副本及回执，不泄露发送企业其他资料。
- `businessImportBatches`：批次标识，整批验证通过后事务提交。

接口：`/api/platform`、`/api/platform/auth`、`team`、`files`、`import`、`network`、`ai`。保留 `/api/finance`、`/api/finance/business`、`/api/tax`、`/api/workspace`、`/api/park` 并加入服务端会话权限保护。旧内容空间仅平台管理员可访问；新企业使用隔离的知识、内容及岗位入口。

## 6. 接入前提与不能冒充完成的能力

- AI模型：用户已于2026-10-27明确授权将本次任务和检索知识发送到DeepSeek官方接口；新增岗位、知识整理和内容已接入。真实调用仍须有效服务端密钥与额度，未配置时只标为本地规则模板。接口字段按[DeepSeek官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)核对，默认deepseek-flash非思考模式。
- 生成式图片/视频：目前交付的是可编辑品牌SVG与模板视频渲染，尚未接通图片/视频生成供应商。
- 外部渠道：内部通知可用；公众号、视频号、小红书的发布须各平台授权和官方接口，不能以“内部已发送”冒充外部发布。
- 现场设备：手工抄表和算费可用；真实IoT设备协议和网关需要现场资料及凭据。
- 支付/税务：内部登记可用；银行支付、税务申报及电子发票不在没有官方授权接口时模拟执行。
- 人事采购为轻量工作流，不包含考勤设备、全套薪资、库存、制造质量或供应链ERP。

这些外部依赖不阻塞内部业务录入、审核、交付、核算、人工收付与追溯，但代表原PDF中全部规划能力尚不能笼统宣称都已完成。

## 7. 验收原则

以真实API调用和持久化数据库验证：匿名访问保护、企业隔离、敏感字段权限、Schema拒绝非法输入、状态流转、版本冲突、跨模块单据去重、档期并发冲突、分次收付和冲销、知识审核与接力、导入原子性、通知回执、附件鉴权。UI核对桌面和手机布局、空状态、核心录入及导出可下载。测试数据仅写入独立验收数据库，不写入正式本地数据。
